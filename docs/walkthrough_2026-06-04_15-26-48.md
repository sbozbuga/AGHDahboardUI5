# Walkthrough: UI5 Bootstrap, Tests, and Cache Busting Fixes

**Status:** COMPLETED
**Date/Time:** 2026-06-04 15:26:48 (GMT+2)

I have successfully completed the implementation plan. Here is a summary of the changes made and the results of verification.

## Changes Made

### 1. Fixed OPA Test Failures (`manifest.json`)
- **What Changed:** Reverted `bundleUrl` to `bundleName: "ui5.aghd.i18n.i18n"` in the i18n model configuration.
- **Why:** `bundleUrl` was causing the translation files to return 404s when running tests because it tried to resolve paths relative to the test runner's URL instead of the component root.
- **Result:** The UI text correctly translates during testing.

### 2. Fixed JSON Parsing Errors (`index.html`)
- **What Changed:** Removed the `#v=1.0.1` fragment from `data-sap-ui-resource-roots` in `webapp/index.html`.
- **Why:** The browser was treating the resource path as a fragment, causing it to request the root HTML page instead of the actual JSON or JS modules it needed.
- **Result:** The application now correctly requests module paths without syntax errors.

### 3. Fixed Library Preload Errors and Implemented Cache Busting (`package.json`)
- **What Changed:** Modified the `build:opt` script. Instead of replacing the bundled `sap-ui-custom.js` with `sap-ui-core.js`, the script now automatically appends a timestamp query parameter (e.g., `?v=1780579425483`) to the `sap-ui-custom.js` reference in the compiled `dist/index.html`.
- **Why:** Reverting to `sap-ui-core.js` broke the self-contained build by forcing the app to fetch libraries that weren't there. Appending the query parameter guarantees cache invalidation on every build without breaking UI5's internal router.
- **Result:** The deployed app will always load the latest code, and 404 MIME type errors for preloads are eliminated.

## Verification

- `npm run test`: Passed (OPA integration tests now load properly and resolve titles).
- `npm run build:opt`: Passed. Verified that the output `dist/index.html` successfully includes the new `sap-ui-custom.js?v=timestamp` query string.
